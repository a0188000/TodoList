## 1. Project Context

### 背景與目標（PRD p1）
- 打造簡潔的 iOS 待辦事項 App：快速記下任務、查看未完成事項、追蹤已完成任務。
- 核心體驗：查看清單 → 輸入任務 → 新增成功 → 回到清單。新增只需填寫名稱。
- 平台 / 語言：iPhone／繁體中文。

### MVP 成功條件（PRD p1）
- 不需登入即可完成查看與新增（免登入為建議規則）。
- 新增成功後，任務立即出現在清單頂端。
- 「待辦」與「已完成」清單呈現正確狀態。
- 取消、重複點擊與儲存失敗不造成誤新增或資料遺失。

### 範圍（PRD p2 功能範圍，全部 P0）
查看待辦清單、新增任務、任務名稱必填與按鈕狀態、取消新增、新增成功回饋、底部 Tab Bar 切換、標記任務完成（設計文案已描述，原型未串接）、查看已完成任務、本機資料保存（建議規則）。

### 不在範圍內（PRD p2）
編輯、刪除、搜尋、排序設定、到期日、提醒、分類管理、帳號、雲端同步、多人協作、恢復未完成操作。
設計中「日常／工作／生活」為示例輔助文字，**不得**據此新增分類功能。

## 3. 畫面規格

畫面對照（PRD p2）：01 待辦清單、02 新增任務・空白、03 新增任務・已輸入、04 新增成功、05 已完成。
**02 與 03 為同一新增頁的不同狀態；04 為清單頁的成功狀態，不建立獨立頁面**（PRD p2）。實際需實作的畫面為 3 個：待辦清單、新增任務、已完成清單，外加底部 Tab Bar 容器。

### 3.1 待辦清單（Screen 01 / 04）— FR-01、FR-03

| 項目 | 內容 | 來源 |
|------|------|------|
| 標題 | 「待辦事項」 | p3 設計已定義 |
| 區塊 | 「我的清單」 | p3 設計已定義 |
| 數量文字 | 顯示全部未完成任務數量；建議文案「還有 N 件事，從一件開始。」（不套用當日篩選） | p3 設計 + 建議規則 |
| 每筆任務 | 左側未勾選圓圈 + 任務名稱；名稱可換行，不截斷 | p3 |
| 排序 | 建立時間由新到舊（新任務置頂） | p3 建議規則 |
| 新增入口 | 明確的「新增任務」入口（清單有資料、空狀態、成功狀態皆需保留） | p3、p4 |
| 空狀態 | 「目前沒有待辦事項」＋新增入口 | p3 建議規則 |
| 捲動 | 清單可垂直捲動；Tab Bar 固定，內容不被遮住 | p3、p6 AC-12 |
| 成功狀態（04） | 新任務置頂並顯示「剛剛新增」、數量 +1、顯示「任務已新增」提示約 3 秒後消失；消失後回到一般版面，「剛剛新增」只在本次成功回饋狀態顯示 | p4 FR-03 |

互動：
- 點擊「新增任務」→ 開啟新增任務頁（無 Tab Bar）。
- 點擊任務左側圓圈 → 儲存完成狀態與完成時間；成功後任務移出待辦清單、數量 −1、出現在已完成清單（p4 建議規則）。
- 圓圈視覺可小於 44pt，但觸控範圍需擴大至 ≥ 44 × 44 pt（p5）。

- Tab 切換保留資料，不重新建立或清空清單（p5）。

### 3.6 互動總覽

| 互動 | 起點 | 結果 | 來源 |
|------|------|------|------|
| 點擊「新增任務」 | 待辦清單（一般 / 空 / 成功狀態） | 開啟空白新增頁 | p2–p3 |
| 輸入名稱 | 新增頁 | 依 trim 結果即時切換兩個新增入口啟停用 | p3 |
| 點擊「新增」或「新增到清單」 | 新增頁（有效） | 提交中停用 → 成功：返回清單 + 成功狀態；失敗：留在新增頁 + 錯誤提示 | p3–p4 |
| 點擊「取消」 | 新增頁 | 返回清單，捨棄輸入 | p3–p4 |
| 點擊未勾選圓圈 | 待辦清單 | 成功：移至已完成、數量 −1；失敗：維持原狀態 | p4、p6 |
| 點擊 Tab | Tab Bar | 切換「待辦」/「已完成」，資料保留 | p3、p5 |
| 已完成列 | 已完成清單 | 無互動（唯讀） | p4 |

### 3.7 資料模型與持久化（PRD p5）

| 欄位 | 用途 | 規則 |
|------|------|------|
| `id` | 任務唯一識別碼 | 新增時產生 |
| `title` | 任務名稱 | trim 後非空、≤ 100 字、可重複 |
| `isCompleted` | 是否完成 | 新增時 false；標記完成後 true，不可逆（本版無恢復） |
| `createdAt` | 建立時間 | 待辦排序（新→舊） |
| `completedAt` | 完成時間 | 未完成為 nil；已完成排序（新→舊）與時間文字 |

持久化要求：
- 本機儲存，支援離線，免登入（建議規則，OQ-03）。
- 重新啟動 App 後保留任務與完成狀態（AC-11）。
- **資料成功保存後才顯示操作成功**；失敗不得顯示成功、不得造成誤新增或資料遺失（p1、p5、AC-13）。
- 無後端、無同步；資料量預期小。

## 6. Acceptance Scenarios

AC-01 ~ AC-14 沿用 PRD p6 編號與語意；AC-15 起為本 spec 依 State Matrix 補充。

### AC-01 開啟 App
- Given 本機已保存若干未完成任務
- When 開啟 App
- Then 預設選取「待辦」Tab，顯示已保存的未完成任務（新→舊）與正確數量文字
- 對應：REQ-03、REQ-04、SV-01 ｜ 驗證：unit test（ViewModel output）+ simulator screenshot

### AC-02 點擊新增任務
- Given 位於待辦清單
- When 點擊「新增任務」
- Then 開啟新增任務頁，欄位空白（顯示 placeholder 與輔助文字、不預填），「新增」與「新增到清單」皆停用，無 Tab Bar
- 對應：REQ-09、REQ-10、SV-11 ｜ 驗證：unit test + screenshot

### AC-03 輸入空白字元
- Given 新增頁
- When 只輸入空白字元
- Then 兩個新增入口仍停用，無法提交，不建立任務
- 對應：REQ-10、SV-12 ｜ 驗證：unit test

### AC-04 輸入有效名稱
- Given 新增頁
- When 輸入 trim 後非空且 ≤ 100 字的名稱
- Then 「新增」與「新增到清單」皆啟用
- 對應：REQ-10、SV-13 ｜ 驗證：unit test

### AC-05 點擊任一新增入口
- Given 已輸入有效名稱
- When 點擊「新增」或「新增到清單」（任一）
- Then 只建立一筆任務（isCompleted = false、createdAt = 現在），返回清單且該任務置頂
- 對應：REQ-01、REQ-12、REQ-17、SV-07 ｜ 驗證：unit test

### AC-06 連續快速點擊新增
- Given 已輸入有效名稱
- When 快速連點新增入口多次（或同時點兩個入口）
- Then 提交期間兩入口停用，最終只建立一筆任務
- 對應：REQ-13、SV-15 ｜ 驗證：unit test

### AC-07 取消已輸入的表單
- Given 新增頁已輸入名稱
- When 點擊「取消」
- Then 返回清單，任務數量與資料不變；再次開啟新增頁時欄位為空（無草稿）
- 對應：REQ-15、SV-17 ｜ 驗證：unit test

### AC-08 新增成功
- Given 待辦有 N 筆
- When 成功新增一筆
- Then 數量文字變為 N+1，新任務置頂並顯示「剛剛新增」，顯示「任務已新增」提示，新增入口仍可用
- 對應：REQ-05、REQ-17、SV-07 ｜ 驗證：unit test + screenshot

### AC-09 標記任務完成
- Given 待辦有 N 筆（N ≥ 1）
- When 點擊某筆的未勾選圓圈且儲存成功
- Then 該筆從待辦移除、數量變 N−1（N=1 時轉為空狀態），並出現在已完成清單頂端，顯示藍色勾選、灰色刪除線與完成時間
- 對應：REQ-19、REQ-21、SV-09、SV-19 ｜ 驗證：unit test + screenshot

### AC-10 切換 Tab
- Given 待辦與已完成皆有資料
- When 在兩個 Tab 間來回切換
- Then Tab 選取狀態正確，兩清單內容正確、不被清空或重建
- 對應：REQ-03、REQ-24、SV-21 ｜ 驗證：screenshot

### AC-11 關閉後重新開啟 App
- Given 已新增任務並完成其中一筆
- When 終止並重新啟動 App
- Then 未完成任務與已完成任務（含完成時間）皆保留
- 對應：REQ-02、SV-22 ｜ 驗證：unit test（store round-trip）+ simulator

### AC-12 清單為空或任務很多
- Given (a) 無未完成任務；(b) 任務多到超出一屏
- When 顯示待辦清單
- Then (a) 顯示「目前沒有待辦事項」與新增入口；(b) 可垂直捲動，最後一筆不被 Tab Bar 遮住
- 對應：REQ-07、REQ-08、SV-02、SV-03 ｜ 驗證：screenshot

### AC-13 新增儲存失敗
- Given 新增頁已輸入有效名稱，儲存會失敗
- When 點擊新增
- Then 不返回清單、不顯示成功提示、不新增任務；保留輸入，提示「新增失敗，請再試一次」，新增入口恢復可重試
- 對應：REQ-02、REQ-14、SV-16 ｜ 驗證：unit test（注入失敗 store）

### AC-14 開啟鍵盤或放大系統文字
- Given 新增頁或清單
- When 開啟鍵盤，或系統文字設為大字體
- Then 輸入欄與主要操作可見可用，文字不重疊
- 對應：REQ-16、REQ-26、SV-04、SV-18 ｜ 驗證：simulator screenshot

### AC-15 標記完成儲存失敗
- Given 待辦有一筆任務，儲存會失敗
- When 點擊該筆圓圈
- Then 任務仍留在待辦、數量不變、不出現在已完成、不顯示成功；可再次點擊重試；錯誤回饋形式依 OQ-04
- 對應：REQ-20、SV-10 ｜ 驗證：unit test

### AC-16 長任務名稱
- Given 任務名稱超過一行寬度
- When 顯示於待辦或已完成清單
- Then 名稱換行完整顯示、不截斷
- 對應：REQ-07、SV-04 ｜ 驗證：screenshot

### AC-17 名稱 100 字上限
- Given 新增頁
- When 輸入超過 100 字
- Then 無法儲存超過 100 字的名稱（具體為限制輸入或停用新增，依 OQ-02 決議）；恰好 100 字可儲存；同名任務可重複建立
- 對應：REQ-11、SV-14 ｜ 驗證：unit test

### AC-18 完成時間文字
- Given 已完成任務的 completedAt 分別為今天、昨天、更早
- When 顯示已完成清單
- Then 分別顯示「今天完成」、「昨天完成」、日期（格式依 OQ-09），以裝置當地時區計算
- 對應：REQ-22、SV-19 ｜ 驗證：unit test（注入固定「現在」時間）

### AC-19 已完成空狀態
- Given 無已完成任務
- When 切到「已完成」Tab
- Then 顯示「尚未有已完成的任務」
- 對應：REQ-23、SV-20 ｜ 驗證：unit test + screenshot

### AC-20 成功提示結束
- Given 剛新增成功（SV-07）
- When 經過約 3 秒
- Then 「任務已新增」提示與「剛剛新增」標示消失，回到一般清單版面，新增入口仍在
- 對應：REQ-18、SV-08 ｜ 驗證：unit test + screenshot

### AC-21 排序
- Given 多筆任務有不同 createdAt / completedAt
- When 顯示清單
- Then 待辦依 createdAt 新→舊；已完成依 completedAt 新→舊
- 對應：REQ-06、REQ-21、SV-01、SV-19 ｜ 驗證：unit test

### AC-22 前後空白處理
- Given 新增頁
- When 輸入「␣␣買牛奶␣」並新增
- Then 儲存與顯示的名稱為「買牛奶」
- 對應：REQ-10、SV-13 ｜ 驗證：unit test

### AC-23 無障礙
- Given VoiceOver 開啟
- When 聚焦待辦/已完成任務與完成圓圈
- Then 可聽出任務名稱與完成狀態（不只依顏色）；圓圈觸控範圍 ≥ 44×44pt
- 對應：REQ-26、SV-24 ｜ 驗證：simulator（Accessibility Inspector）

### AC-24 首次啟動
- Given 全新安裝，無本機資料
- When 開啟 App
- Then 顯示待辦空狀態，已完成也為空狀態，不崩潰
- 對應：REQ-02、REQ-08、SV-02 ｜ 驗證：unit test + simulator

### SV → AC 對照檢查
SV-01~04、07~22、24 皆有對應 AC。N/A：SV-05（PRD 未定義 loading，本機讀取）、SV-06（待 OQ-11）、SV-23（待 OQ-07）。
